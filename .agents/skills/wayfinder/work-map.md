# Work through the map

Use this branch when the user supplies an existing Zaw Wayfinder id or URL.

1. **Load the map.** Run `zaw session link <wayfinder>` to attach this session to the map, then `zaw show <wayfinder>` and `zaw history <wayfinder>`. Orient on Destination, Notes, Decisions so far, Not yet specified, Out of scope, and map notes that say a child is "blocked on Spec #N".
2. **Choose one unit of work.** If the user named a child, inspect it. Otherwise use `zaw ready` as the executable frontier. Use `--include-hitl` only when intentionally selecting Grilling. Before selecting any child, check the map's "blocked on Spec #N" notes; skip a child until each named prerequisite Spec is done. Grilling children are selected by explicit user direction or map context. A child titled "Delivery plan" belongs to `/deliver` (plan mode); leave it to `/deliver map`. When the route to the destination is clear, the unit of work is turning it into Specs (step 8).
3. **Route landing work to a prerequisite Spec.** When the chosen child needs a change to land in the codebase before it can be resolved, create that change as a Spec with `/spec`, passing `--generated-by <wayfinder>`. Copy the Wayfinder's Domain changes relevant to that Spec's project into the Spec's `## Domain changes` section (see step 8). Do not add a Zaw dependency from the child to the Spec. Add a map note naming the prerequisite Spec, the child it unblocks, and the phrase "blocked on Spec #N"; then stop: creating the prerequisite Spec is this session's unit of work.
4. **Start and claim when needed.** Run `zaw start <child>`. Prototype Tasks claim a worktree as `/prototype` describes; research and Grilling work without one.
5. **Resolve the child.** For Grilling, call `/grilling` and `/domain-modeling` and wait for the human. `/domain-modeling` runs in record mode against the Wayfinder: write settled terms and ADR drafts into the Wayfinder's `## Domain changes` section with `zaw edit`, never into the main checkout. For research, call `/research`. For prototype, call `/prototype`. The child's output is a decision, a finding, or a prototype outcome; anything that must land goes back through step 3.
6. **Record completion.** Add the outcome with `zaw comment <child> --message-file <file>` or `--message -`. For a claimed prototype worktree, release and clean up as `/prototype` describes. Then run `zaw done <child> --resolution <slug>`.
7. **Update the map when needed.** Add a Zaw comment to the Wayfinder with the linked gist, graduated fog, newly specifiable children, or out-of-scope boundary. Use `zaw edit` only when the canonical map body must become the updated index.
8. **Turn the destination into Specs.** When the route is clear, define each implementation Spec with `/spec`, passing `--generated-by <wayfinder>`. Copy the Wayfinder's Domain changes relevant to each Spec's project into that Spec's `## Domain changes` section, so the Spec is their single source and `to-tasks` turns them into its "Domain model" Task. Changes for a project with no Spec stay on the Wayfinder; `/deliver` handles docs-only Planned Specs. Each Spec's Notes link the prototype outcome comments it relies on, so implementers can find the prototype branch without it being merged. Once the destination is covered by Specs, add a final map note naming every Spec the map produced (prerequisite and destination Specs), then complete the map with `zaw done <wayfinder> --resolution <slug>`.

Stop after this one unit of work. Other sessions may be working on the same map concurrently, so reload Zaw state before future writes.
